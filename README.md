## 功能

- **钉钉通知采集**：授权通知使用权后，识别系统通知中的打卡结果；信息不完整或时间冲突时进入人工确认。
- **打卡时间规则**：当天最早打卡作为上班时间，最后一次打卡作为下班时间；只有一次打卡时仅记录上班时间。
- **工作日加班**：08:30～09:00 弹性上班，对应 18:00～18:30 下班；正常下班后 30 分钟起算，间隔可设置。
- **周末 / 休息日**：上下班打卡间隔扣除 1 小时，不足 1 小时按 0 计算；调休可切换为工作日规则。
- **工时记录**：今日预计/已确认加班、历史月统计、工作日与休息日分类、缺卡补录和修正。
- **界面**：黑白灰主题，今日、统计、设置三个入口，无广告、无第三方统计。

## 检查更新

在“设置 → 检查更新”中检查新版本。有新版时应用会下载 APK 并校验 SHA-256、包名、版本及签名，再调起系统安装；无新版时提示“已是最新版”。首次使用可能需要允许本应用安装应用，最终安装仍由系统确认。

自动更新版本信息由仓库根目录的 `latest.json` 提供。发布新版本时，需要同步更新版本号、下载地址、SHA-256 和更新说明。

## 钉钉通知采集说明

1. 安装并打开应用，点击“开启通知采集”，在系统页面手动允许通知使用权。
2. 开启钉钉考勤相关消息通知，等待下一次真实打卡通知。
3. 在“设置 → 钉钉通知采集”检查消息，核对待确认记录。

Android 通知监听器只能读取系统实际发送的通知，不能读取钉钉内部页面或未发送为系统通知的消息。通知隐藏、未发送、日期推定条件不满足或后台连接受限时，可能无法自动记录。通知点击事件仅用于本地留痕和状态刷新，不会从钉钉页面抓取数据。

候选通知保存在本机，最多保留 100 条。正式合计不包含缺卡和未确认的预计工时。国家节假日不自动识别，请逐日调整工作日/休息日规则。历史上已消失且此前未采集的通知无法恢复。

## 开发与构建

项目使用原生 Java。可使用 Android Studio / Gradle 8.9、JDK 17、Android SDK 35 构建：

```sh
gradle :app:assembleDebug
```

仓库未附 Gradle Wrapper，需要本地安装 Gradle 或由 Android Studio 配置。也支持 [离线工具链构建脚本](build-local.sh)，设置 `ANDROID_LOCAL_TOOLS` 指向 ECJ 和 Android 构建工具目录。

正式版签名密钥不得提交到仓库。GitHub Actions 签名构建需要配置以下 Repository Secrets：

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`
- `ANDROID_CERT_SHA256`

请妥善备份签名密钥及密码；丢失或更换密钥会导致已安装版本无法直接覆盖升级。
